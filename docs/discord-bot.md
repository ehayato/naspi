# Discord Bot の運用メモ

## スラッシュコマンドの再登録

`/` から呼び出すコマンドは、Discord 側に登録して初めて候補に出る。
次の場合は、再登録が必要になる（ボタンは登録なしで動くが、`/` の候補は古いままになる）。

- コマンドを追加・削除した
- コマンドの名前や説明（`data.name`、`data.description`）を変えた
- 開発モードと本番モードを切り替えた（登録されるコマンドが違う）

### 手順

`DISCORD_APPLICATION_ID` と `DISCORD_GUILD_ID` は Bot のコンテナには渡していないため、`.env` を指定して実行する。

```
cd /mnt/shared/Documents/repos/naspi
docker compose up -d --build bot     # コードを変えた場合は、先にイメージを作り直す
docker exec --env-file .env naspi_bot node /app/js/deployCommands.js
```

最後に `✅ 登録完了！ N 個のコマンドが登録されました。` と出れば成功。Discord のクライアントで `/` を入力して、候補を確認する（反映されない場合は、クライアントを再読み込みする）。

### 注意

- **登録されるコマンドは `NODE_ENV` で変わる。** `devOnly` のコマンド（復元テスト、世代一覧など）は、開発モード（`NODE_ENV=development`）のときだけ登録される。
- **開発と本番が同じサーバー（ギルド）とアプリを使っている場合、最後に実行した側の内容で上書きされる。**
  本番に切り替えたあとは、本番の状態で再登録する。
- 登録は、そのサーバーの既存のコマンドを、今回の一覧で**置き換える**。一覧にないコマンドは削除される。
- 登録できるのは `.env` の `DISCORD_TOKEN` を持つ Bot だけ。トークンは出力に表示されない。

## 通知チャンネル

| チャンネル | 内容 |
|---|---|
| CLOUD | クラウドとローカルの動き（同期、Proton Drive の認証）、日次レポート |
| BACKUP | ローカルと世代管理の動き（バックアップ、スナップショット）、日次レポート |
| LOG | Bot のエラーログ |
| STATUS | Bot の起動通知 |
| COCKPIT | コントロールパネル |

チャンネル ID は `.env` の `DEV_CH_*`（開発）と `PROD_CH_*`（本番）で指定する。
